## 3. Branch consolidation (Approach A)

Work happens on **`release/v0.5`**, cut from `autopoiesis-phase2-pilot` @ `46e4f0d`.

Order of operations:

1. `npm run vault:snapshot -- "before v0.5 consolidation"` — vault-safe checkpoint before any merge.
2. **Merge `main`** into `release/v0.5` — brings the 27 graphify commits. Expected conflict zones: `package.json` (scripts block), `.gitignore`, `.claude/commands/{initialize,close}.md` bodies, `scripts/validate-structure.mjs`, possibly `federation.yaml`. Resolution rule: trunk (v0.5 line) wins on version/identity fields; union wins on scripts, gitignore entries, and command-body features — nothing from either line is dropped silently.
3. **Merge `feat/admin-app`** into `release/v0.5` — brings M1. PR #1 closes as merged once this content reaches `main`.
4. **Gate suite** (must be fully green before touching `main`): `npm test` · `npm run validate:schemas` · `npm run validate:structure` · `npm run selftest` · `npm run version:check` · site build (`site/` `npm run build`).

A red gate stops the line: fix on `release/v0.5`, re-run, never merge partially.

- **Live verification:** `/`, `/docs`, `/federation`, `/about` (and any other top-nav routes present in the build) return 200 and render with the new copy — checked against the live URL, not just the local build.
- **Discoverability:** set repo `homepageUrl` to the live URL; link it from `README.md`.

## 6. Verification & error handling

- Vault snapshot before every merge; `npm run vault:audit` after.
- The gate suite (§3.4) runs after each merge step and again on `main` post-merge.
- Deploy verified end-to-end against the live URL (HTTP 200 + rendered copy spot-check).
- If Pages enablement or the first deploy fails, `main` is still coherent and tagged — the site step is separable and retryable; nothing else rolls back.
