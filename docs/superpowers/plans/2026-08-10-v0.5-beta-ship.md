### Task 11: Pages workflow + enable + live verify

**Files:**
- Create: `.github/workflows/deploy-pages.yml`

- [ ] **Step 1: Write the workflow** (root `npm ci` is required — the site build imports `../../packages/org-os-kms` and reads root `data/`):

```yaml
name: Deploy site to GitHub Pages
on:
  push:
    branches: [main]
    paths: ["site/**", "data/**", ".well-known/**", "packages/org-os-kms/**", "packages/org-os-federation-map/**", ".github/workflows/deploy-pages.yml"]
  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: pages
  cancel-in-progress: true

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 22, cache: npm }
      - run: npm ci
      - run: npm ci
        working-directory: site
      - run: npm run build
        working-directory: site
      - uses: actions/upload-pages-artifact@v3
        with: { path: site/dist }
  deploy:
    needs: build
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - id: deployment
        uses: actions/deploy-pages@v4
```

Note: in CI there are no sibling instance clones — `aggregate-federation.mjs` degrades to unenriched nodes by design (registry `data/instances.yaml` is in-repo). If the build instead hard-fails on a missing sibling or an empty map cache, fix the aggregator/`buildMap` call to degrade (log + continue), not the workflow.
