>

H4 requires H1 + H2 done and H3's `feat/site-pages` landed (its end-state asserts a main-only branch list, so both feature branches must be merged first). H5 requires H1 + H2 done. H6 runs after H1–H5 — inside it, acceptance (WS-H) comes **before** the tag (WS-G). **H7 (adoption kit) overlaps:** its content tasks (I1/I2/I4) may start any time ∥ wave 1 on a `feat/adoption-kit` branch off `origin/main`; I3 needs H3's site landed; I6 (clean-room re-run) needs H6's tag; the org-os session (~2026-09-10) is its deadline.
>
> Every brief embeds the three safety rules a fresh session must know: (1) never `git stash` / `git reset --hard` / the untracked-file-deleting git verb; (2) the pre-commit guard blocks any *command line* containing both "git" and the bare word "clean" — even in messages or filenames — use `git commit -F <file>` when needed (H1's A6 fixes this false-positive class; after it lands on main the workaround is unnecessary, but harmless); (3) stage explicit paths only, never `-A`. Concurrent sessions exist: **re-verify HEAD, branch list, and PR state before acting; if reality diverges from the masterplan's §0, stop and reconcile the masterplan first.**
