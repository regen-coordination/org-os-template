# Admin App M3 (Proposals) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Implement the layered proposal workflow from the spec — a staged change is both a `data/proposals.yaml` entry (governance metadata + EIP-4824 export) **and** a `proposal/<slug>` git branch holding the actual edits. Add proposal mode to the UI (edit "as if the branch were reality", purple-tinted), registry-level diff review, and a transactional ratify pipeline.

**Architecture:** Extends `packages/admin`. The server gains a **proposals engine** that manages branch ↔ entry lifecycle using a **hidden git worktree** (`.admin/worktrees/<slug>`) so the user's working tree is never checked out from under them. Editing in proposal mode routes M1's registry writes into the proposal's worktree instead of the main repo. Ratify merges to the base branch, regenerates schemas, and exports `.well-known/proposals.json`. Spec: `docs/superpowers/specs/2026-07-23-admin-app-design.md` §5.

**Tech Stack:** reuses M1/M2 stack (Hono, simple-git, yaml, Ajv). No new deps. Optional `gh` CLI for PR creation when a remote exists.

**Branch:** `feat/admin-app-m3` off `main` after M1+M2 merge. Work only under `packages/admin/`.

**Prerequisite:** M1 merged (M2 optional — M3 depends only on M1's registry/git/app modules).

**Key invariant:** proposal **entries** are committed to the **base branch** (so the proposals list is complete no matter which branch is checked out); proposal **edits** are commits on the `proposal/<slug>` branch in its worktree.

```ts
import { join } from 'node:path'

const SLUG_RE = /^[a-z0-9][a-z0-9-]*$/
function assertSlug(slug: string): void {
  if (!SLUG_RE.test(slug)) throw new Error(`invalid slug: ${slug}`)
}
export function worktreePath(repo: string, slug: string): string {
  assertSlug(slug)
  return join(repo, '.admin', 'worktrees', slug)
}
export async function createProposalWorktree(repo: string, slug: string, base: string): Promise<string> {
  assertSlug(slug)
  const wt = worktreePath(repo, slug)
  const git = simpleGit(repo)
  await git.raw(['worktree', 'add', '-b', `proposal/${slug}`, wt, base])
  return wt
}
export async function removeProposalWorktree(repo: string, slug: string): Promise<void> {
  assertSlug(slug)
  const git = simpleGit(repo)
  await git.raw(['worktree', 'remove', '--force', worktreePath(repo, slug)])
  await git.raw(['branch', '-D', `proposal/${slug}`]).catch(() => {})
}
```

Note: `.admin/` must be git-ignored in target instances — Task 10 adds it to the app's setup docs; the worktree metadata itself lives in `.git/worktrees` so the checkout dir being ignored is safe.

```ts
import { existsSync } from 'node:fs'
import { readRegistry, registryPath, type Entity } from './registry.ts'

export interface FieldChange { id: string; field: string; before: unknown; after: unknown }
export interface RegistryDiff {
  registry: string
  added: Entity[]; removed: Entity[]; modified: FieldChange[]
}

const byId = (entries: Entity[]) => new Map(entries.map(e => [String(e.id), e]))

export function diffRegistry(baseRepo: string, propRepo: string, name: string): RegistryDiff {
  const base = existsSync(registryPath(baseRepo, name)) ? byId(readRegistry(baseRepo, name).entries ?? []) : new Map()
  const prop = existsSync(registryPath(propRepo, name)) ? byId(readRegistry(propRepo, name).entries ?? []) : new Map()
  const added: Entity[] = [], removed: Entity[] = [], modified: FieldChange[] = []
  for (const [id, e] of prop) if (!base.has(id)) added.push(e)
  for (const [id, e] of base) if (!prop.has(id)) removed.push(e)
  for (const [id, after] of prop) {
    const before = base.get(id); if (!before) continue
    const keys = new Set([...Object.keys(before), ...Object.keys(after)])
    for (const field of keys) {
      if (JSON.stringify(before[field]) !== JSON.stringify(after[field])) {
        modified.push({ id, field, before: before[field], after: after[field] })
      }
    }
  }
  return { registry: name, added, removed, modified }
}
```

### Task 4: Proposals engine

**Files:** Create `server/proposals.ts`; Test extend `tests/proposals.test.ts`

Lifecycle orchestration. `draft` creates the worktree + commits the entry to the base branch. `propose` freezes a summary diff into the entry and (if `gh` + remote) opens a PR. `ratify` merges the branch, runs `generate:schemas`, exports `proposals.json`, removes the worktree. `reject`/`withdraw` keep the entry, remove the worktree.

- [ ] **Step 1: Write failing tests** covering: draft creates entry (status draft, on base branch) + worktree; propose sets status proposed + freezes summary; ratify merges edits into base and sets status ratified and deletes the worktree. (Use `makeFixtureRepo` + seed empty `proposals.yaml`.)

```ts
describe('proposals engine', () => {
  it('draft → edit → ratify lands the change on the base branch', async () => {
    const p = await draftProposal(repo, { title: 'Archive proj', author: 'luiz', base: 'main' })
    const wt = worktreePath(repo, p.slug)
    updateEntity(wt, 'projects', 'proj-001', { id: 'proj-001', title: 'Node Onboarding Program', status: 'archive', type: 'program', lead: 'luiz', contributors: ['ana'], tags: ['nodes', 'onboarding'] })
    await commitDataPaths(wt, ['data/projects.yaml'], 'proposal: archive proj-001')
    await proposeProposal(repo, p.id)
    await ratifyProposal(repo, p.id)
    // base repo now has the change
    expect(readRegistry(repo, 'projects').entries![0]!.status).toBe('archive')
    expect(readRegistry(repo, 'proposals').entries!.find(x => x.id === p.id)!.status).toBe('ratified')
    expect(existsSync(worktreePath(repo, p.slug))).toBe(false)
  })
})
```

- [ ] **Step 3: Write `server/proposals.ts`** — implement `draftProposal`, `proposeProposal`, `ratifyProposal`, `rejectProposal`. Key logic:
  - `slug` = kebab of title + short random suffix (derive suffix from a counter/hash of title+author+existing count — no `Math.random`/`Date.now` at module scope; accept an injectable clock/id or use `crypto.randomUUID().slice(0,4)`).
  - `draftProposal`: `createProposalWorktree`; append entry to `data/proposals.yaml` via `createEntity(repo, 'proposals', {...})`; `commitDataPaths(repo, ['data/proposals.yaml'], 'proposal: draft <id>')` on the **base** repo.
  - `proposeProposal`: compute `summary` via `diffRegistry` across all collection registries between base and worktree; `updateEntity(repo, 'proposals', id, {...status:'proposed', summary})` + commit on base; if `gh` present and a remote exists, push branch and `gh pr create`, store `pr_url`.
  - `ratifyProposal`: `git merge --no-ff proposal/<slug>` into base (via `simpleGit(repo).merge`); run `npm run generate:schemas` (spawn, cwd=repo) — **wrap in try/catch**: on failure set status `ratified-with-errors` and attach log, do NOT throw; export `proposals.json`; `updateEntity` status `ratified`; `removeProposalWorktree`.
  - `rejectProposal`: set status `rejected`/`withdrawn`, `removeProposalWorktree`, keep entry.
