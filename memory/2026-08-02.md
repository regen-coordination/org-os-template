**Focus:** Federation map ("the torch") — an interactive visual of an instance's *external* world (federated instances, frontier peers-of-peers, sources/provenance, ecosystems), designed as the deliberate counterpart to the internal note graph. Full cycle: brainstorm → spec → 14-task TDD plan → subagent-driven execution → holistic review → security fix.

### Key Decisions

- **Surfaces = A + C.** A reusable package instances embed on their public sites, *plus* an operator-side vault artifact openable next to Obsidian's graph. (Rejected: site-only.)
- **Two linked views, not one blended space.** The map is strictly external; crossings between the internal note graph and the map are explicit deep-link portals. Keeps the data model clean and preserves "inside vs outside" as a meaningful distinction.
- **Depth = frontier + curated ecosystems.** Fetch each ring-1 peer's own `federation.yaml` one hop out to render peers-of-peers as dim ring-2 nodes, plus hand-curated ecosystem nodes from `data/ecosystems.yaml`. This is what makes the dark-forest metaphor literal — you see fires you haven't walked to.
- **Visual language = hybrid** (operator chose "all + hybrid"): orbital structure (deterministic rings by hop-distance) × constellation physics (d3-force, draggable, kin to Obsidian's graph) × torchlight atmosphere (luminosity falls off with distance; frontier = embers).
- **Packaging = framework-agnostic web component**, not an Astro component library. `<federation-map>` with d3-force as its only dep; a thin Astro wrapper in `site/` gives Astro ergonomics with zero lock-in. Revisit a real Astro library later if warranted.
- **Strict view/data split.** `org-os-kms` owns aggregation (`render map` → `map.json`); the component never reads YAML. Swap the host, keep the view; swap the view, keep the data — same seam philosophy as kms itself.
- **Frontier fetch is a separate op from rendering.** `render map` reads only the cache, so network failures can never break a build. Stale cache beats broken build.
- **Executed on the `v0.5` trunk, not an isolated worktree.** Packages resolve siblings by relative path and live-enrichment reads real sibling clones; a worktree would have cost a full dep reinstall and hidden the real data. Trade-off accepted deliberately.
- **Deviation from spec §5 (recorded):** portal *index* file (`renders/federation-portals.md`) instead of stamping links into individual KB notes — KB objects are YAML registry rows today, not markdown notes, so there are no boundary notes to stamp yet.
