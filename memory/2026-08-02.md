### Key Decisions

1. **Shape = "A-with-B packaging"** — one framework backend module (a host-provider abstraction every instance can flip to) **plus** a Radicle-first bootstrap path so new communities never touch GitHub. Not a fork, not a single instance.
2. **Open-LLM angle scoped out, minus a thin layer** — rad-org-os is the Radicle substrate; it only guarantees *runtime-agnosticism* (nothing it ships assumes a proprietary model/host). The actual local-LLM runtime is a separate future module near `org-os-hermes`.
3. **v1 = Tiers 1+2** (substrate/sync + collaboration/identity). Tier 3 (CI via `radicle-ci-broker`, GitHub-Pages→node hosting) designed-but-deferred — that's where Radicle's ecosystem is weakest.
4. **Split canonicality by cohort** — new instances are Radicle-canonical from genesis; existing repos stay GitHub-canonical with a rad mirror and flip when their operator opts in. New field `federation.yaml platforms.canonical: github|radicle` selects the driver.
5. **Identity sovereignty tracks hosting sovereignty** — a member `id` is a URI whose scheme matches `platforms.canonical` (`did:key:…` for Radicle-born instances, `github:` otherwise). Enforced by a validator.
6. **Availability is a 3-tier spectrum, honestly framed** — self-hosted seed node (default, max sovereignty) / radicle.garden managed (€4.99/mo, reliability *not* censorship-resistance) / public seeds (public repos only). Documented plainly: Radicle "private" = selective replication, **NOT encrypted at rest** — every allow-listed node and delegate can read. High-threat groups → self-hosted or the Tor profile.
7. **Architecture = host-provider abstraction (Approach A) + standalone package deliverables (C) folded in.** Rejected: bending the KMS knowledge-ingestion connector to carry hosting/collaboration (wrong abstraction); a parallel command set (forks the workflow surface).
8. **Read/write asymmetry is baked into the contract** — upstream `radicle-httpd` is read-only, so *reads* go over HTTP JSON API and *writes* shell to `rad`. **Writes fail loudly** (`WriteUnavailableError`), never a silent HTTP fallback — the sovereignty guarantee.
9. **Governance maps onto Radicle's native identity doc** — `governance.proposal_threshold` → the identity-doc `threshold`, which **is** main's quorum. Corrected mid-flight: Radicle *disallows* an explicit `xyz.radicle.crefs` rule for the default branch; crefs is only for additional protected patterns (e.g. release tags).

### Defects the review process caught (green tests hid all of these)

Every plan ran subagent-driven: fresh implementer → spec-compliance review → code-quality review, fixes re-reviewed.

- **Critical** — `openChange`'s git closure had a no-op fallback, so in production it returned `{ok:true}` **without creating a patch**: a silent write success, the exact failure the fail-loudly guarantee exists to prevent.
- **Critical** — `rad init` requires a git repo *with an initial commit*; the bootstrap only made a directory, so every real run would have failed. (Reviewer verified against live `rad`.)
- **Important** — seed-node Dockerfile used a bash here-string under debian's `dash` → syntax error, node never booted.
- **Important** — genesis stamp was written post-commit, so committed history (and anything a peer sees) kept `genesis_commit: null`.
- **Important** — Plan-1 contract called `whoami()` synchronously, breaking the radicle driver's genuinely-async `whoami`.
- Plus: `rad patch open` doesn't exist (patches = `git push rad HEAD:refs/patches`) — caught *before* coding because the operator asked whether live `rad` was available; a silent malformed-genesis hole (missing `did` guard); a Base58 fixture typo.
