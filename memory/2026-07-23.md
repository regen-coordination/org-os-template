# 2026-07-23

## Built: @org-os/knowledge-commons (org-os-kms v1)

Shipped a reusable Astro knowledge-commons package + reference site — a full
Obsidian-Publish/Quartz replacement with an interactive knowledge graph, adoptable
across org instances. Branch `feat/knowledge-commons`.

**Process:** deep-research (104 agents, 24/25 claims verified) → brainstorm (visual
companion, 8 mockup iterations → Swiss-Technical × organic/transhumanist ASCII,
carmine #D6281E) → 21-task TDD plan → subagent-driven execution with per-cluster
spec+quality review.

**Result:** 30 package unit tests, 4 Playwright e2e, 630 static pages, graph artifact
3,618 nodes / 5,004 edges @ 0.14 MB gz (well under 1 MB budget). Sources mounted:
org-os docs (41), regen-toolkit (266 after excludes), refi-dao (272), refi-bcn (2) =
581 notes.

**Key decisions** (see `docs/superpowers/specs/2026-07-23-org-os-kms-design.md`):
- Own the thin link core (reimplement wikilinks on Content Layer, not BrainDB — it's
  pre-1.0/stale); adopt Graphology + sigma.js + Pagefind + Astro at the edges.
- Content-first IA; graph is a supporting lens (mini-graph in every aside).
- Package is the product; the reference commons proves multi-instance config.
- Static v1, islands-ready.

**Real bugs caught by review/integration (all fixed):**
- Heading-slug divergence: `slugifySegment` vs `github-slugger` (rehype-slug) broke
  `#anchor` links on punctuated/accented headings → now both use github-slugger.
- Duplicate H1: notes opening with `# Title` doubled the layout H1 → strip leading H1.
- `import.meta.url` unreliable in bundled Astro endpoints → anchor ROOT to
  `process.cwd()`, shared from content.config.
- Real content resilience: a regen-toolkit note with a duplicate `status:` frontmatter
  key crashed the build (gray-matter throws) → quarantine + warn + continue (spec §8).
- Slug-collision guard added to buildCommons (multi-content-root sources).

**Notable:** live wikilink report shows 0 missing/0 ambiguous — the real sources use
standard markdown links, so graph richness comes from the 3,037-node semantic (graphify)
layer more than wikilinks. Wikilink infra is ready for vaults that use `[[ ]]`.

**Follow-ups (spec §11):** in-note trail "N of M" box; interactive ambiguity popover;
remote git source loaders (v2); publishing filters before personal-hub adoption;
regen-toolkit migration off Starlight.

Also note: a background scheduled task (knowledge-graph auto-refresh) committed a few
`chore:` commits onto the feature branch during the session — harmless (schema/graph
regen), flag at merge.
